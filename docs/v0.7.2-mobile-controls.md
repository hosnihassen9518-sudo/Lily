# Lily mobile 0.7.2

Install `mobile_app/build/app/outputs/flutter-apk/app-release.apk` over the
previous app. These corrections require no firmware update.

- Setup returns to the Devices home page with “Device added successfully”
  only after registration, naming, optional placement, and backend refresh.
  A failed finalization remains retryable without resending Wi-Fi credentials.
- Light cards show “Turn on” or “Turn off” based on their reported state.
  The previous button always sent `enabled: false`. Light commands now use
  the same API as the device detail screen and disable duplicate presses while
  sending and refreshing.
- Light and generic power commands report an explicit error when the backend
  returns `mqtt_published: false`. A successful publish is not a hardware
  acknowledgment; physical state still depends on the ESP32 MQTT connection.

Validation: all 29 Flutter tests passed; scoped static analysis passed;
independent review found no actionable issues. Physical home-page LED control
requires testing with this APK on the phone.

Acceptance check: turn the LED on from the home card, confirm it illuminates,
then turn it off and confirm it extinguishes. Repeat after controlling it from
the detail screen. Complete device setup and confirm it returns home with the
added device visible and the success message.

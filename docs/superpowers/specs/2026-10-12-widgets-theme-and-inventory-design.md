# Lily widgets, agreed theme and usable inventory

User requests: implement Android and iOS home-screen widgets listing account devices with on/off controls; restore the agreed pastel cloud theme; make automatic inventory generation work without a missing signing-key setup step; add administrator credential/config access, remove/resync actions and CSV export of all metadata or selected fields.

Theme restoration reuses only the visual Flutter files and image from codex/mobile-cloud-theme. Preserve secure mobile sessions, reset-pending behavior and existing device-management screens. Restore lavender/sky/cream/peach, cloud app bars, illustration and two-column cards.

Widgets use native Android AppWidget/RemoteViews and an iOS WidgetKit extension. Android supports a scrolling list, explicit on/off buttons and refresh. iOS17+ widgets show device rows with AppIntent controls (one small, two medium, four large); the main app remains usable on its existing supported iOS versions. WidgetKit schedules refresh, Android requests periodic updates and explicit refresh. Display stale/offline/error states honestly, including pending resets. Never queue power commands when offline and never claim device acknowledgement merely because MQTT accepted a publication.

A widget receives a restricted opaque credential bound to the existing mobile session. The backend accepts it only on dedicated widget read/power routes; it cannot authorize normal account/admin APIs. Parent logout, revocation, inactivity and absolute session expiry revoke widget access. This avoids sharing/rotating the app's refresh credentials from native widget processes. Android encrypts it using Keystore AES-GCM; iOS uses a shared Keychain access group. Public device snapshots contain no token/secret. App login/refresh publishes snapshots and config; logout/backend change clears them. Asynchronous results are bound to the credential snapshot so stale responses cannot repopulate a new account's widget.

Backend power handling locks current device ownership, rejects reset-pending/disabled/offline/sensor devices and sends explicit power state with current MQTT ownership generation. Preserve light brightness/color; power-only devices use generic power commands. Use a new additive Alembic revision for widget credentials and encrypted provisioning archives.

Factory signing-key initialization creates a complete P256 key atomically only when the configured persistent file does not exist. Never replace an invalid/unreadable existing key. Compose retains the key under /data. New generated credentials and config are archived encrypted with a key derived from the persisted signing key; administrator-only retrieval permits repeated show/download. Legacy hash-only secrets are not recoverable and must be reported honestly, never fabricated. CSV uses a fixed field allowlist; selected columns/order are honored, metadata defaults exclude credentials, plaintext secret is an explicit admin-selected field. Neutralize spreadsheet formula cells. Do not export receipt private keys or stored password hashes.

Resync refreshes connection state and resends schedules without changing credentials, as confirmed by the user. Device removal retains existing pending-reset protection.

Verification: theme layout tests on narrow screens and large text, delegated credential/revocation/ownership/expiry and CSV/encryption/key-lifecycle tests, Flutter synchronization races, Android release build and package metadata/native widget registration, iOS project/entitlement/catalog validation. Native iOS build and physical home-screen behavior need macOS/Xcode and a phone; document that limit. Deliver a new APK and reviewable widget branch, do not merge/deploy without further instruction.

Ownership generation is included in each snapshot and captured in native power intents. The backend compares expected_generation under the device lock before publishing. A stale intent cannot command a reset/reassigned device even when the owner is the same.
Factory trust is recorded before first provisioning; absent files initialize only on fresh installations. Lost or mismatched established keys require restoring the original persistent file.

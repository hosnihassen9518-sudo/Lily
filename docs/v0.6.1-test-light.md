# Lily V0.6.1 - Test Light integration

V0.6.1 is based directly on V0.6 and adds the first physical end-to-end test device.

## What changed

- Added backend device type `test_light` with `power` and `light` capabilities.
- Added user-editable device naming during mobile provisioning.
- Added rename-device API and rename action on the device page.
- Added `esp32_test_light/`, a V0.6-compatible provisioning/MQTT firmware for one ordinary LED on GPIO18.
- Added a root `.gitignore` for local secrets, build output, virtual environments, Node/Flutter/PlatformIO artifacts and IDE files.

## Test path

Mobile app -> Lily setup AP -> home Wi-Fi provisioning -> FastAPI activation -> MQTT -> ESP32 GPIO18 -> LED.

The LED uses the same `light` command structure as the future RGB implementation, so replacing the test LED later does not require redesigning the backend command path.

# Lily 0.7.1 BLE setup corrections

Install the updated mobile APK (0.7.1+3) and flash the updated test-light firmware (0.7.1-test-light-ble) together.

Changes:

- A random pairing PIN is generated once and saved in ESP32 NVS. It stays the same across restarts and normal firmware uploads. Erasing NVS/entire flash generates a new PIN. Read the fixed PIN in Serial Monitor; do not confuse it with a number from an old firmware session.
- Android completes system Bluetooth bonding before the app opens its GATT connection. The app then waits for encrypted identity reads and authenticated firmware status before enabling setup. Pairing can take up to 90 seconds; complete the Android PIN dialog/notification.
- After connecting, the app asks the ESP32 to scan nearby 2.4 GHz Wi-Fi. A dropdown shows those SSIDs, signal strength, and security. Scan again is available; Enter manually supports hidden networks. Wi-Fi is temporarily enabled for scanning and stopped afterward if it was previously off. The phone stays on its normal Wi-Fi.
- Wi-Fi scan data is paginated to fit GATT values. Credential writes remain sequential with response and are never automatically resent after an ambiguous error. A failed write disconnects and clears incomplete device input before a manual reconnect.
- The 2 KB message envelope no longer occupies the Bluetooth callback stack. Firmware diagnostics show reset reason, heap, auth result, command chunk byte counts, and setup stages. Passwords/tokens are not printed.

## Install and retry

1. Close Serial Monitor, then from `D:\Projects\Lily\Lily\esp32_test_light` run `pio run --target upload --upload-port COM4`.
2. Open `pio device monitor --port COM4 --baud 115200` and verify firmware 0.7.1 plus the fixed PIN.
3. Install the new APK. For migration from the earlier unstable pairing, forget the old Lily entry in Android Bluetooth settings once, then pair from Add Device using the current fixed PIN. Keep phone Wi-Fi connected to the backend network.
4. Wait for pairing and the ESP32 Wi-Fi list, choose a network/password, then submit. Backend/MQTT host settings still come from firmware `device_config.h`; mobile backend settings configure the phone only.

The missing `/littlefs/wifi.json` at first boot means saved home Wi-Fi is absent; it does not prove a write failure. Credentials are saved atomically after backend activation succeeds. Authentication/write/scan failures occur earlier and should be diagnosed separately.

If GATT 133 recurs, capture Serial Monitor from reset through the failed attempt, including `Lily BLE connected`, authentication result, command chunk lengths, disconnect and any boot/panic messages, plus the Flutter `Lily BLE:` logs. Startup-only logs cannot identify whether the device rebooted, pairing failed, or the radio link dropped. These changes are verified by tests/builds; physical GATT stability needs testing on the user's phone/ESP32.
